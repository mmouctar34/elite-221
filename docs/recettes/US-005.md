## Cas difficiles vérifiés

- **Installation à partir de zéro** : `npm ci` a d'abord échoué sur ce PC, parce que le cache local de npm était abîmé (probablement par la synchronisation OneDrive). Après `npm cache verify`, tout est passé. Ce problème est propre au PC : sur GitHub, chaque exécution part d'un cache neuf.
- **Fins de ligne** : `.gitattributes` impose le même format sur Windows et sur les serveurs de GitHub, pour éviter de fausses différences.
- **Droits** : la vérification n'a que le droit de lire le code (`permissions: contents: read`).

## Défauts trouvés

Aucun dans le projet. Point d'attention sur le PC : le dossier OneDrive synchronise `node_modules` (des centaines de milliers de fichiers), ce qui ralentit et peut abîmer les installations. Voir le rapport du sprint.

## Verdict proposé : Acceptée sous condition

À confirmer par une première exécution réelle sur GitHub, et par l'activation de la protection de `main`, dès la création du dépôt.
