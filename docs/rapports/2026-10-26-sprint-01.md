# Rapport : sprint 1, premières fondations de la PWA

Date : 26/10/2026. Période couverte : 26/10/2026. Commits : `b3569d1` à `d4bd2b0`.

## 1. En une phrase

SPLEAD existe maintenant pour de vrai : une PWA au style Souffle, installable, qui s'ouvre sans réseau, vérifiée par 31 tests automatiques et légère (75 Ko à l'ouverture), mais pas encore en ligne ni essayée sur un téléphone.

## 2. Pourquoi c'était nécessaire

Toutes les fonctionnalités de SPLEAD (leçons, séances, analyses) reposeront sur ces fondations :

- un projet bien organisé ;
- un style commun à tous les écrans ;
- la capacité de s'installer et de marcher hors-ligne ;
- une vérification automatique qui empêche de casser ce qui marche.

## 3. Ce qui a été fait, étape par étape

**Étape 1 : le socle** (branche `sprint1/socle`). Création du projet avec Vite (l'outil qui construit l'application), React (pour les écrans) et TypeScript en mode strict (qui repère les erreurs avant l'exécution). Les bibliothèques sont installées depuis le registre officiel npm :

```bash
npm install
```

(Télécharge toutes les bibliothèques listées dans `package.json`, aux versions notées dans `package-lock.json`.)

**Étape 2 : US-007, le système de design** (branche `sprint1/us-007-design`).

- Les 7 couleurs Souffle sont écrites à un seul endroit (`src/ui/tokens.ts` et `src/ui/styles.css`).
- 9 composants réutilisables : bouton, bouton-icône, carte, pastille, champ, gros bouton micro, barre du bas, chargement, erreur.
- Une page interne `/design` les montre tous.
- Un test calcule automatiquement le contraste de chaque association de couleurs.

**Étape 3 : US-001 et US-003, l'installation et le hors-ligne** (branche `sprint1/us-001-003-pwa`).

- Le **service worker** garde l'application sur l'appareil.
- Le **manifeste** donne son nom, ses icônes et son affichage plein écran.
- Le bandeau « Installer SPLEAD » n'apparaît qu'à la 2e visite.
- Un bandeau « Hors-ligne » s'affiche quand la connexion coupe.

**Étape 4 : US-005, la vérification automatique** (branche `sprint1/us-005-ci`). Le fichier `.github/workflows/verification.yml` dit à GitHub de tout vérifier à chaque envoi. En attendant GitHub, on lance la même chose en local :

```bash
npm run verifier
```

(Enchaîne l'analyse du code, les tests, la construction et la mesure de la taille. Si une étape échoue, tout s'arrête.)

**Étape 5 : la recette.** Chaque user story a été vérifiée critère par critère, avec des preuves (procès-verbaux dans `docs/recettes/`). On a notamment :

- mesuré tous les boutons dans le navigateur ;
- testé l'application avec le serveur coupé ;
- testé un écran de 360 px, avec et sans agrandissement.

Un défaut a été trouvé, puis corrigé (branche `sprint1/correctif-affichage-agrandi`).

Pour voir l'application vous-même sur ce PC, dans le dossier SPLEAD :

```bash
npm run dev -- --port 5180
```

(Lance un serveur de développement. Ouvrez ensuite `http://localhost:5180` dans Chrome, et `http://localhost:5180/design` pour le système de design.)

## 4. Ce qu'il faut retenir

- **Service worker** : un petit programme que le navigateur installe à côté de l'application. Il garde une copie des fichiers, ce qui permet d'ouvrir SPLEAD sans réseau.
- **Manifeste** : une fiche d'identité de l'application (nom, icônes, couleurs, plein écran). C'est elle qui rend la PWA installable.
- **Branche** : une copie de travail du code, séparée de `main`. On y construit une user story, puis on la **fusionne** dans `main` quand tout est vert.
- **Intégration continue (CI)** : un serveur qui vérifie automatiquement chaque modification. C'est ce qui empêche une erreur d'arriver chez les apprenants.
- **Budget de performance** : une limite chiffrée qu'on s'impose (ici 200 Ko à l'ouverture) et qu'on mesure à chaque construction, pour rester rapide sur les petits téléphones.
- **Recette avec preuves** : on ne dit pas « ça marche », on montre comment on l'a vérifié. Et ce qu'on n'a pas pu vérifier est écrit noir sur blanc.

## 5. Ce qui a coincé et comment c'était réglé

- **L'outil d'aperçu ouvrait Madior Insight** au lieu de SPLEAD : il lisait la configuration du dossier Madior et le port 5173 de Madior. Réglé en donnant à SPLEAD ses propres ports (5180 pour le développement, 4180 pour la version de production), et en ajoutant deux entrées SPLEAD dans la configuration locale de l'outil. Ce fichier est ignoré par git : le code de Madior n'a pas changé.
- **`npm ci` a échoué** à cause d'un cache npm abîmé sur le PC, sans doute à cause de OneDrive, qui synchronise en permanence les milliers de fichiers de `node_modules`. Réglé avec `npm cache verify`. Conseil : à terme, déplacer les projets de code hors de OneDrive (par exemple dans `C:\Projets`), car git et GitHub servent déjà de sauvegarde.
- **Débordement avec l'affichage agrandi à 200 %** : la pastille de l'accueil et un onglet dépassaient de l'écran. Corrigé : les mots trop longs passent à la ligne, et les marges sont réduites sur les très petits écrans.
- **Le garde-fou de l'extension ECC** demande une justification avant chaque nouveau fichier, ce qui a beaucoup ralenti le sprint. Il peut être assoupli dans les réglages d'ECC si vous le souhaitez.
